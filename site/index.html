Grimalkin

Your assistant's familiar. A self-hosted memory and context layer for Claude, over MCP.

Grimalkin keeps a durable model of your life: the people, projects and facts your sessions teach it, plus your calendar and contacts. It serves all of it to Claude on your phone, your laptop or Claude Code from one endpoint you own.

View on GitHub Install step by step

Runs no model

Your client does the reasoning with Grimalkin's tools. There are no API keys to buy and no per-call model cost. Memory changes only when a session writes to it.

One owner

Single-tenant by design. One deployment, gated to one Google account through a small OAuth 2.1 server. Read and write are separate scopes.

Your database

Everything lives in a Postgres database you run. Deletes are soft and reversible, and every fact carries its confidence and where it came from.

What it does

Grimalkin gives any MCP client a set of tools for remembering, recalling and briefing, backed by a graph of people, organisations and projects.

Remembers

Keeps entities with facts and links, each with confidence and provenance.

remember · forget · restore · update_entity · merge_entities · move_facts

Recalls

Returns what is known about someone or something, ranked and narrowed by topic, then searches raw source material.

get_context · search · what_do_you_know

Briefs

Reads your calendar and attaches what it knows about the people you are about to meet.

upcoming · brief

Learns how you work

Serves an operating policy you write plus preferences your sessions notice. Preferences gain confidence each time they are seen again.

how_i_work · note_preference

Stays fresh

A background worker syncs Google Calendar and Contacts on a schedule and runs a daily retention sweep.

read-only calendar and contacts scopes

Works everywhere

One remote MCP endpoint for Claude on the web, desktop and mobile, and for Claude Code.

https://<your-host>/mcp

How it fits together

One build, two processes. The MCP service serves the tools and handles sign-in. The worker ingests. Both share one Postgres database with pgvector.

Claude mobile  ─┐
Claude Desktop ─┼─→  mcp service  ─→  Postgres + pgvector  ←─  worker
Claude Code    ─┘    (MCP tools,      (episodes, entities,     (ingest + retention)
                      OAuth 2.1)       facts, links)              ↑
                                                         Calendar, Contacts

Get started

You need Node 22+, pnpm, Postgres with pgvector, a Google Cloud OAuth client and an HTTPS host. Plan on about an hour. The self-hosting guide walks through every step, including a Railway deployment. Or let the install wizard walk you through it and write your settings for you.

Clone and install

git clone https://github.com/webfeathers/grimalkin.git
cd grimalkin
pnpm install
cp .env.example .env

Set up Google and the database

Create one OAuth client, mint the worker's token, then migrate and check everything.

pnpm mint:google work
pnpm db:migrate
pnpm doctor

Deploy and connect

Run the MCP service and the worker from the same build, then add https://<your-host>/mcp as a custom connector in Claude and sign in with Google.
